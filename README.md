# agent-guardian

跨 CLI 运行期监督与讨论组编排。在另一个终端会话旁边挂一个监督者：它按固定节奏观察目标（pi / codex / 普通终端），发现原地重复、进展停滞、连续失败、上下文压力时按梯次干预——先提醒，再警告（需要回应确认），仍未确认则暂停待命；只有命中客观硬边界（如删除工作区外路径、向外部主机外泄凭据）才会停止目标。预算到期时监督者写汇报并自己退出，不动目标。需要判断时，可以把证据交给只读的判断者命令，或拉起一个讨论组收集多个独立意见。

**零运行时依赖**：不安装任何第三方包，直接 `node scripts/guardian.ts` 运行（Node ≥22.18，推荐 24；type-stripping 免编译）。

## 一、挂一个监督者（最常见用法）

在主会话里说一句话（例如"挂个监督者，用 codex 看着我"），主 Agent 读到自己的终端句柄后执行：

```bash
orca terminal split --terminal $ORCA_TERMINAL_HANDLE --direction vertical \
  --command "node C:/PiWorkbench/packages/agent-guardian/scripts/guardian.ts watch --terminal $ORCA_TERMINAL_HANDLE [--llm ...]"
```

监督者与主 Agent 同屏分栏，用户零操作。没有会话文件时是纯活性监控；加上 `--session` 则同时解析 pi/codex 会话记录（按内容自动识别）。

## 二、命令

### watch

```bash
guardian watch --terminal <句柄> [--session <会话文件>] [--contract <契约文件>] [--llm "<命令>"] [--budget-min 120] [--remind-max 5] [--llm-max-calls 3] [--retention-days 14]
guardian watch --file <会话文件> [--contract <契约文件>]
```

- `--terminal`：监督 Orca 里的一个终端（完整能力：提醒、警告、暂停、停止）。
- `--file`：纯观察模式——tail 一个会话文件（pi/codex 的 .jsonl），只写记录与汇报，不向任何终端发消息。没有 Orca 也能用。
- `--session`：配合 `--terminal` 给出会话文件，按内容自动识别 pi 或 codex 会话。
- `--contract <path>`：任务契约 JSON `{requirement, acceptance[], scope[], approvedDecisions[]}`。启动时校验存在性与形状，非法 → 退出码 2（不进入监督循环）。契约内容进每次外部判断的证据包与完工汇报头部，全程不可变。
- `--llm "<命令>"`：启用只读判断者（默认命令建议 `pi -p`）。有信号反复出现时，监督者先把证据包写成 JSON 文件，再把固定判断者提示词（含证据文件路径指令与输出 JSON 格式）作为最后一个参数传给该命令，读取其标准输出中的决定。决定必须是 JSON：`{"action":"silence"}`、`{"action":"remind","message":"..."}`、`{"action":"pause","message":"..."}` 或 `{"action":"panel","question":"..."}`。判断者只读、证据按不可信数据处理、禁止修改代码；输出不合法 → 本次按沉默处理并记录；输出 `stop` → 一律降级为暂停（停止权在监督者内核）。不传 `--llm` 则全程机械判断。外部判断与同种信号的提醒共用冷却窗口，并受全局上限约束（见 `--llm-max-calls`）。
- `--budget-min`：监督时长预算，默认 120 分钟。到期时监督者写完工汇报并自己退出（退出码 0），不动目标——不会警告或停止目标。
- `--remind-max`：轻提醒上限，默认 5 次；超过后升级为需要回应的警告。
- `--llm-max-calls`：每次监督的外部判断调用全局上限，默认 3 次；超过后回到机械梯次路径（不再咨询）。
- `--retention-days`：证据保留期（天），默认 14；`watch`/`events` 启动时清理超过保留期的旧记录。

**干预梯次（默认机械路径）**：

1. 信号触发 → 提醒（轻提醒，只含机械事实与行动建议；冷却 3 拍，有上限）。
2. 同一信号提醒后复现 → 警告：文案升级为"需要你的回应确认"，事件记录标记待确认。
3. 警告未获确认且信号复现（或出现新证据）→ 暂停待命（可逆）：提示目标暂停核对，事件升级并在汇报/事件流中置顶。暂停后目标仅回应文本不算复工——出现新的工具调用才算复工（记录复工事件）。
4. 停止只用于客观硬边界：监督者每拍扫描目标会话的最近命令，命中硬边界模式（删除工作区外路径，含根目录删除；向外部主机发送含凭据的请求）才停止目标。模式表保守判定，不确定即不停止；无硬边界命中时内核任何情况下不停止目标。

### panel

```bash
guardian panel "<问题>" [--n 3] [--backend orca|headless] [--out <目录>] [--materials <路径>...]
                 [--agent <名称>] [--member-cmd "<命令>"] [--synthesize-cmd "<命令>"] [--no-synthesize]
```

1. 生成成员任务说明（问题 + 材料节选 + 独立作答要求 + 候选方案格式）。
2. 同时派出 n 名成员独立作答（orca 后端用 Orca 的 worker 机制，用户可见；headless 后端并行执行 `pi -p` 或 `--member-cmd` 自定义命令）。
3. 收齐 `member-<i>.md`（每名成员最多等 30 分钟，超时记失败、不阻塞其余）。
4. 综合为 `panel-result.md`（候选方案、共识、分歧、推荐与理由、少数派意见）；`--no-synthesize` 只写归并索引。
5. 释放成员（orca 后端）。

- `--synthesize-cmd "<命令>"`：自定义综合命令，监督者把产出目录作为最后一个参数传入，命令负责写 `panel-result.md`。默认用 `pi -p` + 内置综合提示词。

### events / report

```bash
guardian events [--watch <id>] [--retention-days 14]   # 查看事件流（不指定则列出全部）
guardian report --watch <id>          # 输出/重新生成完工汇报
```

- 升级事件（暂停待命 / 硬边界停止）在事件流中置顶输出；完工汇报中同样置顶展示。
- 汇报头部含任务契约（`--contract` 挂载时）。

## 三、数据目录

`~/.agent-guardian/`（`AGENT_GUARDIAN_HOME` 可覆盖）：

- `state/` 监督状态（每次节拍原子落盘，崩溃后从最近一拍恢复）
- `events/` 事件记录（只追加）
- `reports/` 完工汇报
- `panels/` 讨论组产出
- `tmp/` 外部判断用的证据包

## 四、行为边界

- **默认沉默**：只在机械信号触发时发声；同一问题提醒后冷却 3 拍，轻提醒有上限。
- **干预可逆**：警告需要回应确认；未确认且信号复现 → 暂停待命（可逆，新工具调用即复工），不再自动停止。预算到期监督者自己退出，不动目标。
- **停止是最后的硬边界**：只有删除工作区外路径（含根目录）、向外部主机外泄凭据等客观可观测边界才停止；发出停止信号后会轮询确认目标真的停下（有界重试），结果记入事件（stop-verified / stop-unverified）。纯观察模式（`--file`）不发送任何消息，所有干预只记录。
- **同一 handle 同一时刻只有一个监督者**：每次启动生成新的运行代（watchRunId）与代际（generation），状态文件保持稳定名；已有未过期租约且属主进程存活时拒绝启动（单例锁，退出码 3）；属主进程已死且租约未过期才走崩溃恢复（继承旧状态）；租约过期或上次已正常收尾则视为新任务（不继承旧计数）。状态文件读取真失败（如 EBUSY 瞬态重试耗尽、权限等）→ 中止启动，不写任何状态/事件/报告，退出码 4（可重试，瞬态清除后正常）；无状态文件（ENOENT）才是首次运行的静默 fresh。
- **外部判断只出现在判断点**：节拍、游标、状态、冷却、预算、落盘、执行全部是确定性代码；判断者输出只作建议（停止建议一律降级为暂停）。
- **无外部依赖**：信号引擎与提取逻辑随包内置（`src/shared/`），本包可独立检出运行，不需要任何同级项目。

## 五、证据卫生与保留期

- 写入事件/证据包前执行秘密脱敏：常见密钥形态（AKIA…、sk-…、Bearer …、PEM 私钥块）替换为 `[REDACTED]`，命中的事件标 `redacted:true`。
- `guardian watch` / `guardian events` 启动时清理超过保留期（默认 14 天，`--retention-days` 可配）的旧记录：状态、事件、汇报、讨论组产出、证据包整组删除。

## 六、注意事项

- 数据目录里的一切都是本机文件，不会上传；记录文件是纯文本，可随时删除。
- 监督终止不删除任何会话数据；讨论组只写产出目录。
- 详细设计见 `docs/design.md`。
